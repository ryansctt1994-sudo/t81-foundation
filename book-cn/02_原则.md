# 第 2 章：核心原则与不变性

## 2.1 确定性不变性

**状态：已实现并测试**

T81 架构的中心公理是**严格的确定性**。一个 T81 程序是一个纯函数 $f(S, I) \to S'$，其中 $S$ 是初始状态，$I$ 是输入。该函数必须在任何兼容的硬件平台上产生位一致的 $S'$。

实现这一点需要消除现代计算中所有常见的非确定性来源：
*   **硬件浮点数**：由软件定义的 `T81Float` (`dmath`) 取代。
*   **内存布局**：逻辑地址与物理指针解耦。
*   **并发**：线程调度由确定性协程和逻辑时钟取代。
*   **系统时间**：墙上时钟时间由 Lamport 时间戳（逻辑时钟）取代。

### 2.1.1 确定性表面与攻击向量

下表映射了非确定性可能泄露到系统中的“表面”以及 T81 采用的具体缓解措施。

| 层级 | 确定性风险 | 缓解措施 | 证据 |
| -------- | ---------------------------- | ------------------------- | ----------------------- |
| 编译器 | 令牌顺序 | 规范 AST 发射 | `scripts/ci/t81lang_repro_gate.py` |
| VM | 内存地址泄露 | 无地址可观察性 | `src/vm/vm.cpp` (内存段) |
| GC | 非确定性回收 | 分配计数触发 | `src/vm/vm.cpp`: `run_gc_cycle_` |
| 浮点 | 宿主 FPU 漂移 (IEEE-754) | `dmath` 软件浮点 | `include/t81/core/T81Float.hpp` |
| JIT | 优化分歧 | 基于追踪的等效性 | `src/vm/jit_compiler.cpp` |

> **验证**：`src/vm/jit_compiler.cpp` 中的 JIT 编译器确保优化后的追踪在与解释器基线发生*任何*状态分歧时退出 (`GuardDeopt`)。

## 2.2 三进制逻辑 (Base-3)

**状态：已实现并测试**

T81 是一个**平衡三进制**系统。基本单位是 **trit**，值为 $\{-1, 0, 1\}$（通常表示为 $-, 0, +$）。

### 2.2.1 为何选择三进制？
1.  **对称算术**：舍入只是向最近整数的截断，因为 $0.5$ 在 base-3 中如果没有无限扩展是无法表示的分数。这简化了 `dmath` 库。
2.  **信息密度**：基数 $3$ 比 $2$ 更接近 $e \approx 2.718$，提供了整数基数经济性（$\text{radix} \times \text{width}$）的理论最优值。
3.  **有符号表示**：负数不需要符号位或补码。首位 trit 自然指示符号。

### 2.2.2 实现
在 C++ 代码库中，trits 为了效率被打包，但在逻辑上是独特的。
*   **存储**：`T81Int` 在打包形式中使用每 trit 2 位（参见 `include/t81/packing.hpp`）。
*   **算术**：像 `Add`, `Mul` 这样的操作在 `src/vm/vm.cpp` 中使用模拟平衡三进制进位链的整数数学实现。

## 2.3 可审计性与 Axion 追踪

**状态：已实现并测试**

T81 中的每个状态转换都是可审计的。**Axion 内核** 生成一个称为 **追踪 (Trace)** 的执行加密日志。

### 2.3.1 追踪结构
追踪是 `AxionEvent` 记录的序列，捕获操作码、裁决及相关数据。

> **参考**：参见 `include/t81/axion/api.hpp` 获取事件定义。

## 2.4 九项原则 (伦理强制执行)

**状态：已实现并测试**

T81 将不可变的伦理层（九项原则 $\Theta_1 \dots \Theta_9$）直接嵌入到 VM 的策略引擎中。这些不是指导方针，而是 **运行时约束**。

例如：
*   **$\Theta_7$ (熵遏制)**：防止在没有显式 `InfExpand` 许可的情况下无限资源扩展。
*   **$\Theta_4$ (可解释性)**：强制要求不透明的“黑盒”张量不能在没有伴随元数据或符号图的情况下发射。

> **实现**：这些检查在 `src/axion/ethics.cpp` 中执行。违规将导致 `VerdictKind::Deny` 和立即的 `Trap::SecurityFault`。
