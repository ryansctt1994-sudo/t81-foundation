# Roadmap for T81Lang Evolution

This roadmap outlines the plan for implementing missing features and addressing gaps identified in the T81Lang audit. It prioritizes semantic correctness and modularity over feature expansion.

## 1. Cognitive Tier Enforcement (Semantics for Syntax)
**Status:** Syntax exists (`recurse`, `distributed`, `infinite`), but implementation is transparent (pass-through).
**Goal:** Ensure these blocks emit TISC instructions that allow the VM/Axion to enforce tier-specific policies.

- **Phase 1: Metadata Emission (M)**
  - **Task:** Modify `IRGenerator` to emit `META_TIER_ENTER(tier_id)` and `META_TIER_EXIT` instructions at the boundaries of these blocks.
  - **Acceptance:** `t81 compile` produces bytecode with explicit tier markers. `tisc-disasm` shows them.
  - **VM Support:** VM treats them as NOPs or logs them for now.

- **Phase 2: VM Enforcement (L)**
  - **Task:** Update T81VM to trap on `META_TIER_ENTER` if the active Axion policy forbids that tier (e.g., `policy.allow_distributed = false`).
  - **Acceptance:** A `distributed { ... }` block faults deterministically when running under a restrictive policy.

## 2. Standard Library Modularity
**Status:** Stdlib is hardcoded as thousands of lines of `if-else` in `IRGenerator::visit(CallExpr)`.
**Goal:** Decouple intrinsics from the compiler core.

- **Phase 1: Intrinsic Registry (M)**
  - **Task:** Refactor `IRGenerator` to use a `static const std::unordered_map<string, OpcodeGenerator>` table.
  - **Acceptance:** Code size reduction in `ir_generator.hpp`. No change in generated bytecode (bit-exact regression test).

- **Phase 2: T81 Definition Files (L)**
  - **Task:** Allow defining "extern" functions in `.t81` files that map to opcodes, removing the need for C++ changes to add standard library functions.
  - **Acceptance:** `std/math.t81` contains `extern fn sin(x: T81Float) -> T81Float = "FSIN";`.

## 3. User-Defined Generics
**Status:** **NOT IMPLEMENTED**. Parser accepts syntax, lowering ignores it.
**Goal:** Support type-safe generic functions.

- **Phase 1: Monomorphization (XL)**
  - **Task:** Implement template instantiation in the Semantic Analyzer. When `foo[T81Int](...)` is called, generate a specialized `foo_T81Int` function in the IR.
  - **Acceptance:** `fn id[T](x: T) -> T { return x; }` works for `T81Int` and `T81Float` in the same program.

## 4. Deprecations
**Status:** PDF claims exist for "Auto-GPU", "AI-Compiler".
**Goal:** align expectations with reality.

- **Action:** Explicitly mark these features as "Conceptual / Research" or remove them from documentation.
- **Reason:** T81 is a deterministic stack machine; "magic" optimization conflicts with the core tenet of determinism. Optimization should be explicit (e.g., via `optimize(tensor)` intrinsic) or handled by the JIT transparently, not claimed as a language feature.
